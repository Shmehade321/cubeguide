# T07 rendering implementation notes

These notes refine the approved T07 contract; they are not implementation or qualification evidence. The authoritative requirements remain Documentation/cube-app-specification.md, cube-app-implementation-plan.md and cube-app-verification-plan.md. T06 calculation regression must finish and its increment must be committed before changing Swift sources for this work.

## Contract and boundaries

R07/R08/R12/R16 and V02/V10/V14 require A02's 26 visible cubies and 54 stickers, beveled bodies/gaps, neutral lighting, visible interior surfaces during turns, exact layer membership and resting transforms, distinct turn/regrip arrows, no accumulated drift and usable non-color/Reduce Motion alternatives. T07 also includes A01 and A03–A07 provenance/visual qualification. An attractive static cube alone does not satisfy T07.

GuideAction already carries identity, operation, before/after Facelets and from/to CubeOrientation. The renderer consumes that value. It must not solve, mutate canonical input, change a session index, save an acknowledgement or manufacture physical completion. SessionController's GuidePlayback callback reports preview completion only. T08 retains ownership of coordinated media sequencing and final guide integration.

Manual input can be incomplete. Its preview must render the actual explicit center palette and optional cells, with an unmistakable empty-sticker appearance; it must not fill missing entries with solved colors. Semantic color labels remain separate from mathematical Face identity. Practice uses its isolated controller and copied preferences.

## Implementation order and behavioral evidence

1. **Exact geometry before rendering.** Add pure integer lattice/sticker placement types to CubeCore, with no RealityKit/UIKit imports. Map the URFDLB row-major convention to 26 noncentral positions and 54 outward normals. Write assertions for every index, center, top edge and corner; each sticker belongs to exactly one cubie. Cover the eight three-sticker corners, twelve two-sticker edges and six one-sticker centers. Observe behavioral RED before filling the implementation. Never derive expected placements by calling the production geometry being tested.
2. **Turn and pose geometry.** For all 18 moves and 24 poses, compare uniquely identified sticker destinations to the checked-in golden move fixture and existing canonical orientation behavior. A face turn selects exactly nine cubies/21 stickers; a regrip selects all 26/54 and preserves Facelets. Verify proper rotations, inverse operations, all half/inverse turns and no reflected frames. The independent test geometry oracle remains test-only and must not become the production move engine.
3. **RealityKit scene adapter.** Build procedural body/sticker entities from the exact placements, with one model-owned entity identity per cubie/sticker. Use a SwiftUI UIViewRepresentable around ARView in explicit non-AR mode, automatic camera-session configuration disabled, and a virtual PerspectiveCamera showing front/right/top. This avoids a camera permission dependency for manual/practice rendering. Apply a fixed virtual camera and original procedural lighting/materials; no remote assets or meshes.
4. **Endpoint-first animation tests.** A selected-layer pivot animates the layer as one group; a regrip animates the root. Sample a monotonic presentation timeline to set absolute transforms rather than accumulating frame rotations. On completion, rebuild/snap from exact action.after/toPose data. Tests inspect rendered entity membership and exact endpoints independently of frame timing. Long-run sequences, replay, pause/resume, reset, interruption and obsolete callback identity must not drift or advance logical progress. Test supplied clocks/controls in the platform adapter; no real-time sleeps for mathematical expectations.
5. **Visible action semantics.** Add original procedural arcs/arrows and a layer highlight for turns; use a whole-cube outline for regrips. Derive their direction from the same GuideAction. Test every view/front-turn amount and every regrip endpoint, including inverse/half-turn labeling. Add front/top/right color anchors and readable non-color labels. Inspect real rendered before/mid/after frames in light and dark modes; a transform-only test cannot prove arrow visibility or understandable direction.
6. **Reduce Motion and manual preview integration.** Provide labeled static before/after presentation without an endless render loop. Add the real incomplete-draft 3D preview to the existing editor and a solved-cube/checkmark completion graphic. Expose view controls with accessible labels; free preview rotation must return to instruction pose before guidance resumes. Test that viewing changes neither draft revision nor physical acknowledgement. Qualify 375/430-point layouts, narrow landscape and largest text; add VoiceOver/device evidence later rather than equating accessibility identifiers with usability.
7. **Remaining original art.** Produce the original icon/vector source and install its actual asset; create three help/onboarding illustrations and six top-neighbor diagrams from the orientation contract. Register original sources/provenance in the existing asset manifest. Keep absent human narration/effects explicitly missing for T08 rather than substituting speech synthesis. A08 store screenshots remain T12 release-build output.

Each coherent increment retains focused RED/GREEN evidence, runs relevant suites and the full PR plan, inspects actual rendered output, updates task-07 evidence and is committed before proceeding. Tests added for pre-existing behavior are labeled as added coverage; mutation failures are labeled as mutation evidence rather than fabricated missing-feature RED cycles.

## Framework checks and selected adapter

Apple documents [PerspectiveCamera](https://developer.apple.com/documentation/realitykit/perspectivecamera) for a virtual viewpoint with ARView.CameraMode.nonAR, [generateBox(size:cornerRadius:)](https://developer.apple.com/documentation/realitykit/meshresource/generatebox(size:cornerradius:)) for procedural centered beveled boxes, and [Scene.subscribe(to:on:_:)](https://developer.apple.com/documentation/realitykit/scene/subscribe(to:on:_:)) for retained scene-event subscriptions. Check actual declarations against the installed SDK and iOS 18 deployment target when implementing; successful use of a newer SDK alone is not availability evidence. Subscription cancellation, view teardown and offscreen work belong in lifecycle tests.

## Completion limits

Physical arrow/golden-cube checks, sustained 30 fps on baseline phones, accessibility observation, novice comprehension, actual media and release distribution remain required. Simulator geometry, screenshots and unit tests cannot close those gates. No graphics code or asset is claimed implemented by this plan.

Installed-SDK preflight (Xcode 27.0, before graphics implementation): inspected the iPhoneOS SDK RealityKit/RealityFoundation arm64e Swift interfaces. The explicit ARView initializer accepts cameraMode and automaticallyConfigureSession; CameraMode includes nonAR. PerspectiveCamera, MeshResource.generateBox(size:cornerRadius:), SceneEvents.Update and Scene.subscribe are declared with iOS 13 availability. The newer major/minor-corner-radius overload is iOS 18. This is declaration/availability evidence only; forthcoming builds, simulator rendering and physical qualification must establish actual behavior. Prefer the established single-corner-radius overload for the initial scene.
