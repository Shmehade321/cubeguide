## Solver model and tables

`CubeSolver3` owns independent cubie permutations, coordinate codecs, bounded binary parsing and an immutable resource loader. T04 adds bounded two-phase IDA* with 12/18 depth limits, admissible paired-distance heuristics, same-face pruning only within each phase, and fresh move history at the phase boundary. `CubeTableTools` and `TableGenerator` are development-only targets; the application does not depend on them.

`Scripts/verify-tables.sh` verifies the generator source against the manifest's source commit, generates into two clean directories, compares both with the packaged files, and runs the independent Python/NumPy oracle. The oracle reconstructs every move transition via facelet geometry, recomputes every distance, checks all outgoing edge distance bounds and predecessors, and verifies corruption detection. Install its pinned development requirements with `python3 -m pip install -r Tools/TableValidator/requirements.txt` when not already available. They never become an app dependency.

Runtime resources are limited to ten files with known dimensions and a bounded manifest. Complete-file SHA-256, version, path, dimensions, counts and value ranges are checked before exposing tables. Search uses the loaded immutable arrays with checked coordinate inputs. Loader cancellation is checked between bounded file operations; device cancellation latency remains a T04 qualification obligation.

## Search orchestration and qualification

`SolverService` is an actor that cancels and awaits a replaced worker before starting another. CPU work runs in a detached task, with a lock-protected cancellation token and immutable shared tables. Request identity prevents an already-computed stale answer from reaching the consumer. `SolverRuntime` uses a monotonic clock and independent CubeCore replay; only `VerifiedPlan` can become guidance. The app dependency container owns one service; manual-entry UI comes at T06.

`Scripts/test-solver.sh` runs the tier selected in `TestPlans/corpora.json`, all 46,741 shallow states, named hard/invalid fixtures, and the pinned Java differential reference. Every answer is also replayed with the independent Python geometry oracle. Corpus/result hashes, versions, raw durations and every failure are retained. The PR tier uses 10,000 unique states; nightly 100,000 with a recorded daily UTC seed; release one million. `CUBE_CORPUS_SEED` can reproduce another recorded seed. Java 11 is the reference runner default; `JAVA_HOME` may specify a compatible installed JDK, whose exact version is recorded.

Run `python3 Tools/MutationChecks/core.py`, `python3 Tools/MutationChecks/solver.py` and `python3 Tools/MutationChecks/session.py Artifacts/new-session-mutation-run` sequentially with no concurrent Swift builds: each temporarily edits sources and restores them. Mutations count only when a discovered test produces a behavioral failure. Do not equate desktop warm benchmarks or simulator integration with the outstanding physical iPhone cold/warm benchmarks, whole-app memory or cancellation-latency gate.

## Guide persistence composition

The app dependency container links CubeSession and owns one SessionStore for `Application Support/CubeGuide/Guide`. That actor exclusively serializes writes and deletion for the directory. A storage lease belongs to a producer generation; deletion invalidates prior leases. GuideArchive validates bounded, checksummed snapshots by independent replay and action reconstruction before restore opens physical comparison. Temporary files are not confirmed records. Guide and manual-draft archives use the same bounded checksum envelope and atomic replacement implementation; one deletion lease owns both files.

The store excludes its directory from backups and requests complete file protection on iOS before writing the payload. File access failures propagate; only ENOENT means no saved guide. Simulator integration verifies the real solver/reducer/save/restore composition, not hardware encryption or locked-device behavior. The observed simulator does not expose the protection attribute; physical assertions and lock testing remain an open qualification gate. Manual UI and settings integration are described below; the guide UI and diagnostics store remain subsequent work.

## Accepted scan observations

`CubeScan` depends only on CubeCore and Foundation. CubeSession depends on CubeScan and retains public aliases for the existing CubeColor, CenterPalette and PaletteError names; encoded center palettes keep the same representation. Callers using palette members explicitly import CubeScan under Xcode member-import visibility; CubeScan is also an explicit application package product dependency. The new immutable ScanDraft holds six canonical slots populated in F,R,B,L,U,D capture order. Each accepted face contains nine measurements, optional manual overrides, an explicit optional center name, capture metadata and the recorded correction rotation. It has no image field or completion-proof API.

CaptureMetadata describes the upright, unmirrored processing image while retaining source orientation/mirroring provenance, the explicit cube pose and a bounded sampling-version identifier. Coordinates and sizes are bounded; four corners must form a clockwise convex quadrilateral. The normalized cross-product cutoff of 1e-8 rejects numerical degeneracy; it is not a tuned camera-quality or confidence threshold. Actual frame normalization, homography, sampling, quality assessment, six-center classification and the production camera adapter remain subsequent work. Synthetic observation fixtures prove these value contracts, not recognition accuracy.

Scan persistence uses the existing draft.json/draft.pending pair. DraftArchive decodes the unchanged legacy manual shape or an explicitly tagged PendingScan payload inside the bounded checksum envelope. Pending scans bind recovery/verification to the exact retained Guide SaveID; a partial scan never replaces the active guide. SessionRestoration returns both records in one actor snapshot. SessionController exposes pendingScan and prevents unrelated manual/guide commands from resuming the retained guide while scan input remains active. The coordinator executes capture-state commands; root UI remains unfinished. Global deletion covers scan data through the existing draft paths and lease invalidation.

The pure ScanWorkflow reducer separates asynchronous freezing, transient face review and accepted-observation persistence. Its commands carry per-workflow operation identities; only matching callbacks can advance, and interruption requires an explicit physical resume check. Initial context, accepted faces and full-scan corrections pass through save barriers. Shared ScanFace edits apply the same rotation/override behavior before and after acceptance. The reducer is verified independently and with the real store using synthetic observations; SessionController command execution is described below.

SessionController now executes ScanWorkflow commands and exposes camera readiness. Its injected ScanCamera adapter is optional for manual-only use; starting a new scan without one fails before persistence. Scan startup reads a fresh store snapshot and retained Guide SaveID, checks context/consent/revision bounds, then persists before starting capture. Controller generations plus per-camera-run tokens reject late readiness/interruption/frame callbacks. Lifecycle events route to the active scan, and global deletion stops capture and shares the ordered storage queue. App composition exercises this with an explicit fixture camera; the production AVFoundation/image-processing adapter and root UI remain unimplemented.

Confirmed draft discard writes a tagged, bounded revision marker into the existing draft file, retaining only its revision and optional guide SaveID. It replaces manual/scan input without changing guide bytes. Storage leases rotate before writing, including failed attempts; retries repeat synchronization. Restore preserves the input revision high-water mark separately from the retained guide/action revision, so new manual/scanned work cannot reuse a discarded revision. Retained guidance may advance after physical comparison; late plans from discarded input are rejected. Unknown/corrupt files remain available for confirmed global deletion rather than selective interpretation.

SessionController exposes saving/failed discard status, requires confirmation, stops camera/playback and cancels solving immediately, and serializes discard behind earlier writes. It adopts restored state only after durable success; failed callbacks leave input blocked for explicit retry or global deletion. Generations reject late frame/save/solve callbacks. These contracts are exercised through real host storage and installed-app composition with a fixture camera; product discard controls, production camera and physical-device qualification remain unfinished.

Scan-to-manual fallback takes an explicitly confirmed six-center palette and copies only accepted manual sticker overrides into a newer ManualDraft. Existing rotation corrections are already reflected in those override positions. Measured/provisional colors are not guessed; other cells remain empty for manual entry. A pending accepted-face save can be included, while an unaccepted frozen review must first be accepted or left. The controller stops capture, serializes the manual write behind prior work, blocks editing until success, and offers explicit retry/global deletion after failure. Generation checks reject old camera/write callbacks. Manual validation and entered-color completion semantics apply even when the source scan was a verification scan. The center-assignment/fallback controls and final classified-scan acceptance remain UI/integration work.

The session mutation catalog requires a passing unmodified baseline, unique patch targets, completed behavioral failures and byte-identical source restoration. Its 17 seeded defects cover core session durability and identity contracts; reports remain finite evidence rather than exhaustive bug coverage. The nightly script invokes the catalog after normal regression, while its broader qualification ledger still fails on missing required evidence.

## Settings and manual UI integration

The manual app now composes SessionController directly: Home, explicit center assignment, durable sticker editing, validation/correction, consent, verified search results, entered-color completion and local Help are implemented. These supersede the earlier foundation-stage notes about absent manual screens. The complete guide/camera interfaces remain pending; implemented practice isolation is described below.

AppPreferences stores only narration/effects/haptics, guide speed and color-label preference. SessionStore owns preferences.json/preferences.pending under the same actor, bounded checked envelope, atomic replacement, backup exclusion and protection policy as cube records. An absent settings file yields documented defaults; invalid or future records surface a load error and cannot be silently overwritten. No UserDefaults API is introduced by this implementation. This is not a completed archive privacy audit.

The observable controller queues settings writes with other durable work and only publishes a changed preference after confirmed success. An ambiguous failure retains the exact candidate for explicit retry. Confirmed deletion cancels producers, invalidates callbacks, removes the preferences pair with the existing cube files and resets the displayed defaults after success. Scan lifecycle events and matching save callbacks remain deliverable while settings are saving. Operations that replace the controller generation cannot strand a settings save.

Settings and Help pause media/capture through the shared auxiliary-navigation operation. Visible editor sticker letters respect the stored preference, while Differentiate Without Color forces them on without modifying that preference. Full accessibility names and review symbols remain independent of letter visibility. Sound/haptic settings and guide speed are persisted for the upcoming presentation adapters; their presence is not proof of implemented playback, narration assets or physical haptics. Release qualification remains tracked in the evidence ledger.
