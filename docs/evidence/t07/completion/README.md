## Largest-text follow-up

The first dark-mode/largest-accessibility-text run passed normal guide completion but failed the Reduce Motion test before completion. [The failure image](accessibility-first/failure.png) and [hierarchy](accessibility-first/failure-hierarchy.txt) show Play partly behind the navigation bar: XCTest reported it hittable but its center tap was obscured. The test helper now requires a visible control frame when it fits, otherwise a visible center, before tapping.

An incremental rerun still executed the old early-return interaction sequence. A fresh build and reinstalled runner executed the new helper; its [landscape diagnostic](accessibility-clean/landscape-stall.png) then exposed a second helper error: the visible navigation bar began below the reported scroll-view top, so the old overlap condition failed to subtract it. That diagnostic was intentionally interrupted, and its logs are retained. The helper now subtracts every intersecting visible navigation bar. The owned simulator's interrupted Reduce Motion setting was restored before reboot and the final focused run.

Fixed-length gestures subsequently overshot a large acknowledgement control; the helper now uses measured drags toward the viewport center and fails explicitly if a control cannot be revealed. The [corrected focused run](accessibility-passed/summary.json) passed with all ten actions acknowledged, static artwork and separate physical confirmation. Inspected [normal](accessibility-passed/normal-largest-dark.png) and [static](accessibility-passed/17192F7D-471F-4A3B-B392-3CACBCA496E5.png) largest-text/dark completion captures. The original simulator settings were restored. No product changes were needed for these test-helper issues; the final full PR passed after the helper correction.
