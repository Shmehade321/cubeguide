## Increment 3 — bounded guide archive and restoration

GuideArchive version 1 stores an explicit schema, base64 JSON payload and SHA-256 of the exact payload bytes. The entire encoded file is capped at 256 KiB before decode. Unknown versions are identified before interpreting version-specific payload fields; filesystem preservation of unknown files remains the store's next obligation. The checksum detects corruption, not authenticity.

The payload preserves the original canonical state, bounded move notation, original hash, resource version, explicit semantic palette, save ID, acknowledged action count, move index, pose, acknowledged state, pending action ID and preparation marker. Decoding validates legality, independently replays the full plan through Replay, reconstructs the deterministic action timeline and requires exact agreement with saved state/pose/index/identity. A checksummed payload cannot bypass those semantic checks. Resource versions are nonempty and capped at 256 UTF-8 bytes; sequence zero and a prepared action after completion are rejected.

Restoring into Session opens resumeCheck, or expectedSolved when all actions are durable. It retains the write sequence, has no pending write/playback, and resets alignment permission. The caller retains the restored explicit palette separately from the mathematical Session. No camera swatches, draft files or completion-origin persistence is claimed here; those remain T05 integration work.

## Increment 4 — actor-owned guide filesystem store

GuideStore owns one dedicated directory through one actor instance. It reads at most 256 KiB + one byte and delegates all archive validation to GuideArchive. Missing files return no saved guide; malformed/oversized/unsupported files throw and survive attempted saves until explicit deletion. Production composition must own exactly one instance for the directory; independent stores in tests represent sequential process reopen, not supported simultaneous writers.

Saves write a same-directory `guide.pending`, synchronize and close its file handle, atomically rename to `guide.json`, then synchronize the directory. A pending file is never promoted to acknowledged progress on load. Later saves replace abandoned pending bytes; deletion removes both files. Backup exclusion is set on the owned directory. iOS file protection, Application Support path composition and actual locked-phone behavior remain required adapter work; this increment does not claim them.

An opaque lease identifies the current store generation. Deletion invalidates it before touching files, runs behind an in-flight synchronous actor write, and returns success only after removals/directory synchronization succeed. Even failed deletion rejects old producers. Save ordering rejects older revisions/sequences and conflicting payloads at an already-durable ID. A same-ID exact snapshot may be safely rewritten. Global deletion still needs orchestration across draft/preferences/diagnostics and the Session reducer; this store currently owns only the guide archive.
